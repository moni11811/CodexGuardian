# Development and testing

## Architecture

```text
Codex task -> MCP helper ----\
Mac app -> authenticated IPC ---> Guardian daemon -> SQLite journal/outbox
CLI ------------------------/           |
                                         +-> policy and task projections
                                         +-> Codex recovery adapters
Experimental iPhone -> pinned TLS gateway/
```

The daemon is the durable state owner. The menu app, MCP helper, CLI, and phone client are clients. Destructive authority must never be duplicated between them.

## Engineering rules

- State the observed bug theory before patching.
- Add a regression that fails for the exact symptom first.
- Do not retry a deterministic failure unchanged.
- Preserve intent before side effects.
- Unknown evidence fails closed.
- Keep source/build/install/live proof and GitHub publication as separate claims.
- Do not claim a hard restart from tests alone.

## Test lanes

### Fast source lane

```bash
swift test
./script/test_mcp.sh
```

This covers pure policy, journal, IPC, client, phone-core, app-server protocol fixtures, and MCP framing. It does not prove the installed application or real Desktop behavior.

### Packaging contracts

```bash
./script/test_production_build_contract.sh
./script/test_daemon_launch_contract.sh
./script/test_launch_environment_contract.sh
./script/test_install_activation_diagnostics.sh
./script/test_transactional_install.sh
./script/test_credential_provisioning.sh
./script/test_release_metadata.sh
```

These protect release configuration, daemon-owned socket setup, clean launch environment, named activation failures, rollback, local credential permissions, and metadata. They do not install unless the script explicitly says so.

### Production Mac lane

```bash
./script/install_production.sh
./script/test_production_install.sh
```

This changes `/Applications`, launchd jobs, state credentials, and running Guardian services. Run only on an authorized Mac. The installer can stop/restart Guardian processes, but it must not restart Codex.

### Recovery and failure-injection lane

Relevant scripts include:

```text
test_gate0_appserver_recovery_protocol.sh
test_gate0_live_proof_driver.sh
test_gate0_recovery_harness.sh
test_installed_codex_appserver_gate0.sh
test_journal_crash_replay.sh
test_agent_execution_policy.sh
test_agent_execution_runtime.sh
```

Read each script before use. “Gate 0” fixtures and standalone app-server results are not proof of the existing Desktop UI. Live proof must name the exact task, exact message ID, exact turn, and evidence source.

### Benchmark lane

```bash
swift run guardian-bench --seed 42 --revision "$(git rev-parse --short HEAD)" --output result.json
```

GuardianBench is deterministic pure-policy evidence. It performs no network calls and proves only its named scenarios.

### iPhone lane

The project is generated by XcodeGen:

```bash
cd Phone
xcodegen generate
xcodebuild -project CodexGuardianPhone.xcodeproj \
  -scheme CodexGuardianPhone \
  -sdk iphonesimulator \
  -configuration Debug \
  CODE_SIGNING_ALLOWED=NO build
```

A simulator build is not device, network, background, pairing, mutation, TestFlight, or App Store proof.

## CLI reference

```bash
guardianctl                 # authenticated daemon snapshot
guardianctl codex-process   # trusted Codex app/process inspection
guardianctl codex-control   # current Desktop control evidence
```

Production path:

```text
/Applications/Codex Guardian.app/Contents/SharedSupport/guardianctl
```

The CLI intentionally returns short generic errors. Do not weaken trust checks to make diagnostics easier.

## Public-source preflight

```bash
./script/check_public_repo.sh
git diff --check
git status --short
```

Inspect every tracked and untracked file manually. Generated builds, databases, logs, test results, screenshots, and local config must remain outside Git.

## Claim boundaries

| Evidence | May claim | Must not claim |
| --- | --- | --- |
| Unit tests | named contract passes | live recovery works |
| Source build | code compiles | installed app works |
| Production verifier | installed services and IPC work | Codex task continued |
| MCP smoke fixture | MCP protocol works | Codex loaded it live |
| Same-task delegation receipt | native queue reached exact task | hard restart works |
| Simulator build | iOS UI compiles | phone product works |
| Local ad-hoc signature | local bundle integrity | trusted public publisher/notarization |
